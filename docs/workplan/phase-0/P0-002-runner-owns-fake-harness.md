# P0-002: The runner owns the fake harness and the page shows its output live

**Phase:** 0 — A sandbox you can talk to
**Shape:** seam
**Dependencies:** P0-001 (compile: the composition root, config loader, and page shell
this wires the runner into)

## Objective

While a person is attached through the page or `winch stream`, each valid line the
sandbox's own harness emits appears live as an ordered record, followed by a terminal
record that distinguishes a clean exit, a failure, and a signal.

## Scope

- Build `internal/runner/` around the composition root P0-001 left in
  `cmd/winch-sandbox/main.go`: one runner starts one child with `exec.CommandContext`,
  owns its stdin/stdout pipes, pumps stdout, waits exactly once, and stops and reaps the
  child during sandbox shutdown. Stderr is drained without logging its content; startup
  and pipe failures fail sandbox startup with content-free errors rather than leaving a
  healthy page with no harness.
- Decode the fake harness's existing newline-delimited JSON dialect
  (`cmd/fake-harness/main.go:21-36`) incrementally, retaining an incomplete line between
  reads so arbitrary pipe chunking cannot split or duplicate a record. A decoded line is
  `{kind, payload, sensitivity?}`; reject unknown top-level fields, preserve `payload` as
  JSON, and default an omitted sensitivity to `user-content`. Malformed-line recovery
  and the maximum line size belong to P0-007; until then a bad line is skipped without
  stopping the stdout pump, and the child's eventual terminal record is still emitted.
- Define the Stage 0 session record as
  `{ordinal, kind, occurredAt, sensitivity, payload}`. `ordinal` is a JSON integer,
  allocated by the runner from 1 with no gaps for records it accepts; `occurredAt` is a
  UTC RFC 3339 timestamp generated by the runner; `sensitivity` is always present; and
  `payload` remains JSON. There is no `sequence`, `eventId`, or `schemaVersion` because
  the control plane adds its own envelope in a later roadmap stage.
- Publish accepted records to all readers currently attached to the session through a
  bounded channel per reader. This task may wait when that channel is full; P0-007 makes
  publication non-blocking by evicting the slow reader. Do not retain history for a
  reader that attaches late: P0-003 adds the store and snapshot half of the attach
  contract. Cancellation removes the reader and closes its writer goroutine.
- Emit `session.terminated` exactly once after stdout has been drained and the process
  has been waited. It has `operational` sensitivity and payload
  `{"outcome":"completed|failed|stopped","nativeExit":{"exitCode":N}}` for an ordinary
  exit or `{"outcome":"stopped","nativeExit":{"signal":"SIGTERM"}}` for a signal.
  Exit zero maps to `completed`, nonzero to `failed`, and a signalled wait status to
  `stopped`; the exit code or signal is mutually exclusive.
- Repair the fake's current signal path (`cmd/fake-harness/main.go:67-75`): after its
  final operational observation, restore the signal's default action and re-signal the
  process so `Wait` receives the native signal instead of the current artificial exit
  zero. Keep that behavior covered in `cmd/fake-harness/main_test.go`, and remove the
  dangling comment at `cmd/fake-harness/main.go:29` that names a deleted fixture.
- Extend P0-001's `attach.Server` constructor with the runner's subscription surface and
  register `GET /api/session/stream` as a WebSocket. Use the already-declared
  `github.com/coder/websocket` dependency. Accept clients without an `Origin` header
  (the CLI) and same-host browser origins only; reject a foreign browser origin before
  upgrading. Send one JSON session record per text message, close normally after
  `session.terminated`, and apply a finite write deadline. Other methods still receive
  P0-001's 405 response.
- Extend P0-001's one-command `cmd/winch/main.go` dispatch with
  `winch stream [--url URL]`. Reuse its default base URL and finite connection timeout,
  translate HTTP(S) to WS(S), print each record as one compact JSON line, and exit zero
  only after a `session.terminated` record; an upgrade failure, malformed record, or
  premature disconnect exits nonzero. This is the maintained hands-on surface for the
  seam.
- Extend P0-001's `App.tsx` without replacing its posture fetch. A
  `useSessionStream` hook owns one WebSocket for the component lifetime; `RecordList`
  appends records in arrival order, renders content as text (never HTML), identifies a
  terminal outcome, and exposes a visible disconnected state instead of silently
  freezing. It shows only records received while that page instance is attached.
- Make `fake` the only accepted `WINCH_HARNESS_PROFILE` value and construct its argv
  from `WINCH_HARNESS_TRANSCRIPT`, `WINCH_HARNESS_DELAY`,
  `WINCH_HARNESS_FORCE_FAILURE`, `WINCH_HARNESS_EARLY_EXIT`, and
  `WINCH_HARNESS_MALFORMED_LINE`. Parse durations and booleans strictly before starting
  the child. Generate one opaque session identifier at sandbox startup and pass it as
  the fixture's required `-run-id`; the flag name remains fixture vocabulary and does
  not introduce runs. `deployments/compose.yml` selects `fake` and forwards the
  controls, while the image's existing `/usr/local/bin/fake-harness` is the executable.
- Add a non-terminating transcript fixture with enough lines for both clients to attach
  to the image for the live-output demonstration. The demonstration overrides delay so
  both clients can attach before its later records. `deployments/README.md` documents
  every control and states that the fake does not prove tool calls, approvals, usage
  reporting, login, terminal semantics, or a vendor dialect.
- Pin the newly defined record and WebSocket operation in `docs/contracts.md` and in a
  byte-for-byte golden fixture under `test/contract/attach/`. This contract update is
  part of the task because the API operation and record schema do not yet exist in the
  design document at HEAD.

## Non-goals

- Records before a reader attaches, persistence, snapshot reads, or replay on reload.
  P0-003 adds the store and `GET /api/session/records`; this task is live-only.
- Heartbeats, a caught-up marker, reconnect-from-ordinal, or automatic reconnect. Those
  are roadmap Stage 2's rejoin guarantees, even though `docs/contracts.md` describes the
  destination attach contract.
- Input of any kind. P0-004, P0-005, and P0-006 own the three closed loops on the input
  path.
- `HarnessDriver`, `HarnessCodec`, capability descriptors, or
  `internal/adapters/harness/`. Roadmap Stage 1 introduces the second harness case that
  forces that seam; harness ownership remains in `internal/runner/` here.
- More than one record projection. This page renders the raw record list; roadmap Stage
  2 adds another projection.
- Turning malformed output into a diagnostic, bounding decoder lines, or disconnecting
  a stalled reader. P0-007 owns those adversarial guarantees.
- Restarting a harness in a live sandbox. A terminated session stays terminal; starting
  another sandbox starts another session.

## Runtime reachability

`cmd/winch-sandbox` constructs the runner, passes it to the attach server, and starts its
fake harness before serving until shutdown. The `sandbox` service in
`deployments/compose.yml` selects `WINCH_HARNESS_PROFILE=fake`; `winch stream` and the
page's record list subscribe to the same in-process publisher over the composed
loopback-only WebSocket.

## Contract surfaces

- schema: session record `{ordinal, kind, occurredAt, sensitivity, payload}` and the
  runner-local ordinal allocation
- registry namespace: record kinds, initially `stream.raw` and `session.terminated`
- `session.terminated` payload and native-exit-to-outcome mapping
- API: `GET /api/session/stream` (WebSocket, live records only)
- profile namespace: `fake`
- config keys: `WINCH_HARNESS_PROFILE`, `WINCH_HARNESS_TRANSCRIPT`,
  `WINCH_HARNESS_DELAY`, `WINCH_HARNESS_FORCE_FAILURE`,
  `WINCH_HARNESS_EARLY_EXIT`, `WINCH_HARNESS_MALFORMED_LINE`
- CLI: `winch stream [--url URL]`

## Demonstration

    $ WINCH_HARNESS_TRANSCRIPT=/opt/winch/fixtures/live-output.txt \
        WINCH_HARNESS_DELAY=2s \
        docker compose -f deployments/compose.yml up --build -d
    $ ./bin/winch stream | tee /tmp/winch-stream.jsonl & stream_pid=$!
    → expect: compact JSON stream.raw records arrive in increasing ordinal order while
      the transcript plays; the command remains attached because the harness remains up

    $ xdg-open http://127.0.0.1:8080
    → expect: later transcript lines appear as text in the page while `winch stream`
      shows those same records; profile container-standard and its unenforced network
      egress remain visible

    # signal the child, not the sandbox, so both attach clients remain observable
    $ docker compose -f deployments/compose.yml exec sandbox \
        sh -c 'kill -TERM "$(pidof fake-harness)"'
    → expect: both clients see the fake's last stream.raw observation followed by one
      session.terminated record with outcome "stopped" and native signal "SIGTERM";
      winch stream then exits zero
    $ wait "$stream_pid"
    → expect: exit 0

    $ WINCH_HARNESS_FORCE_FAILURE=true WINCH_HARNESS_DELAY=2s \
        docker compose -f deployments/compose.yml up -d --force-recreate
    $ ./bin/winch stream
    → expect: session.terminated has outcome "failed" and native exitCode 1

## Acceptance criteria

- [ ] A valid line emitted while two readers are attached becomes exactly one record
      for each reader, with the same ordinal; a line split at every possible byte
      boundary is neither duplicated nor lost.
- [ ] Accepted records have contiguous runner-global ordinals from 1, UTC RFC 3339
      timestamps, an explicit sensitivity, and none of `sequence`, `eventId`, or
      `schemaVersion`; the golden fixture checks the complete JSON shape byte for byte.
- [ ] Exit zero produces exactly one `session.terminated` record with `completed` and
      exit code 0; `-force-failure` produces `failed` and exit code 1; sending SIGTERM
      to the harness produces `stopped` and signal `SIGTERM`. In every case the terminal
      record follows all stdout records and `winch stream` observes it before exiting.
- [ ] Killing the child does not kill or freeze the attach surface: the page changes to
      a visible stopped state, `/healthz` remains healthy, and no second terminal record
      appears.
- [ ] An attached page and `winch stream` show transcript records as they arrive; a
      second reader does not steal records from the first. Neither claims to replay
      records emitted before it attached.
- [ ] A foreign browser Origin cannot upgrade, while the same-host page and the
      no-Origin CLI can; the rejected request starts no subscription.
- [ ] Invalid profile, duration, or boolean configuration prevents sandbox startup
      with a content-free error. With `-delay`, measured spacing between controlled
      transcript records changes while their values and order do not.
- [ ] `deployments/README.md` documents the fake controls and states what it does not
      prove, including tool calls, approvals, login, terminal semantics, and that its
      dialect is invented.
- [ ] The fake's signal test proves the child retains native signal status, and
      `cmd/fake-harness/main.go` no longer cites a fixture absent from the tree.
- [ ] P0-001's posture, loopback-only publication, non-root container, standing
      scenario, and all repository gates still pass unchanged.
